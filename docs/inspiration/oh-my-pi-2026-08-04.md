## Scope and decision

Oh My Pi is useful as a coding-harness and interoperability reference, not as a
normative upstream. Grok Build remains normative for the agent loop, sessions,
tools, permissions, hooks, scheduler, TUI, headless mode, and ACP. The review
does not authorize importing Oh My Pi's replacement application architecture,
provider routing, credentials, TUI, session format, or update mechanism.

No Oh My Pi source, assets, or dependencies were copied into Enhanced during
this evaluation. Its MIT license was reviewed, but no distributed third-party
material changed and no notice update is required for this documentation-only
record. A later port must independently review the exact source and license,
update notices when required, and add focused ownership and tests.

## Recommended candidates

| Priority | Candidate | Why it is useful here | Adoption boundary |
| --- | --- | --- | --- |
| P0 | Tool/model regression harness | Exercises real coding tasks across tool combinations and model/provider variants instead of relying only on unit contracts. | Build an Enhanced-native harness around existing headless and session surfaces; never reuse cross-provider credentials. |
| P0 | Kimi forced-tool and reasoning regression | Captures a provider-specific failure mode where forced tool calls and reasoning streams interact. | Add adapter-level fixtures and entitled live tests without adopting Kimi OAuth or another agent loop. |
| P1 | Deeper LSP operations | Adds references, document/workspace symbols, call hierarchy, rename preparation, code actions, formatting, and diagnostics beyond Enhanced's current basic language operations. | Extend the existing Grok tool and permission model rather than exposing an alternate protocol surface. |
| P1 | Syntax-aware search and edit preview | Structural matching and a pre-apply diff can make large edits safer and more precise. | Keep hashline and existing patch semantics compatible; require explicit permission and preview contracts. |
| P1 | Debug Adapter Protocol integration | Breakpoints, stepping, scopes, and variable inspection would make the harness materially stronger for debugging tasks. | Implement as isolated tools governed by existing process and permission controls. |
| P1 | Broader project-instruction discovery | Improves interoperability with repositories that use multiple established instruction-file names and nested scopes. | Preserve `AGENTS.md` precedence and make discovery deterministic and testable. |
| P2 | Review workflow | A focused read-only review mode can improve issue reporting and patch verification. | Compose existing sessions, tools, and permissions; do not introduce a parallel application mode. |
| P2 | Persistent evaluation records | Makes model/tool comparisons reproducible across releases. | Store only redacted fixtures and results; never retain credentials or authenticated payloads. |
| P2 | Small reader and commit-planning utilities | Targeted URL extraction, document ingestion, and commit grouping could reduce manual workflow steps. | Prefer narrow additions to existing tools and preserve current commit/user-approval boundaries. |

## Already covered or substantially equivalent

- Hashline-oriented file editing and basic language-server assistance.
- Subagents, durable memory/context, web search and fetch, PDF/document reads,
  shell completions, hooks/plugins, sessions, headless operation, and ACP.
- Provider-aware model catalogs and tool routing, implemented under Enhanced's
  stricter provider identity and credential-isolation rules.

These areas may still supply individual regression fixtures, but they do not
justify duplicating their runtime architecture.

## Audit-only provider ideas

Oh My Pi's Codex compression, WebSocket transport, and provider-specific stream
handling are useful comparison targets when the Codex adapter is refreshed.
They are not evidence that Enhanced should change wire behavior. Any adoption
requires comparison with the pinned official Codex source and tests for current
Responses semantics, continuation state, retries, cancellation, usage, and
credential redaction.

## Explicit exclusions

- Oh My Pi's agent engine, TUI, session storage, provider selection, update
  route, URL scheme, browser/desktop integrations, and collaboration model.
- Kimi OAuth or credentials that conflict with Enhanced's experimental
  API-key-only Kimi Code provider.
- Retry-after-partial-output behavior that could duplicate side effects.
- Any direct code port without exact-source attribution, license review,
  focused manifest ownership, and regression tests.

## Suggested implementation order

1. Add the Enhanced-native tool/model harness and Kimi forced-tool fixture.
2. Expand the existing LSP tool with tests for project and permission behavior.
3. Prototype syntax-aware search plus edit preview behind explicit contracts.
4. Evaluate DAP as a separate, permission-gated tool family.
5. Add instruction-file interoperability and the smaller workflow utilities.

Each candidate remains unimplemented until it receives its own scoped design,
ownership entry, tests, and—when code is ported—notice review.
